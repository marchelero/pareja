## 1. Resumen ejecutivo

Implementar un modelo **freemium híbrido** para Pareja:

- **Free tier** (default): todos los 14 juegos disponibles, pero con **caps diarios** en algunos.
- **Anuncios rewarded**: cuando un juego sin jugadas disponibles lo requiere, el usuario ve un video corto y gana **+1 jugada extra** para ese juego.
- **Premium** ($4.99 USD, pago único no-consumible vía Google Play Billing): **sin caps, sin anuncios**, hot mode ya viene con verificación persistida de edad.

Punto de inyección único: el botón **EMPEZAR** de cada `*_start_screen.dart`. El mismo flujo de gate, la misma UI de "watch ad OR get premium", aplicado a los 14 juegos.

**Web (Flutter Web deploy):** no hay soporte oficial (decisión user). AdMob y Google Play Billing no funcionan en web. La app sigue compilando para web, pero los usuarios de web quedan en free tier sin acceso a ads ni compras. Capped games a 3/día sin relief. Sin código web-specific.

## 2. Modelo de monetización

### 2.1 Tiers

| Tier | Juegos | Anuncios | Hot mode | Precio |
|------|--------|----------|----------|--------|
| **Free** | 14 disponibles, **5 con cap diario** (medianos) | Sí, rewarded opcional para cap relief | **Bloqueado: requiere Premium** | $0 |
| **Premium** | 14 sin límite, sin cap | Sin anuncios | **Desbloqueado** (después de age gate una vez) | $4.99 USD one-time |

**Decisión del user:** Hot mode es **premium-only**. Free users ven el candado y CTA a paywall. El age gate modal solo se dispara para premium users que activan hot mode por primera vez. La edad se persiste como bool (Phase 2 ya hizo esto).

### 2.2 Reglas diarias (free)

| Tier de juego | Juegos | Cap default | Anuncio recompensa | Premium |
|---------------|--------|-------------|---------------------|---------|
| **Pesado** (contenido denso, larga duración) | Yo Nunca, Preguntas, Sin Palabras | **Sin límite** | No aplica | Sin límite |
| **Mediano** (ritmo medio, contenido moderado) | Chupitos, Ruleta, Bomba, Alto al Fuego, Duelo | **3 / día** | +1 jugada (ese juego) | Sin límite |
| **Ligero** (rápidos, re-jugables infinitamente) | A Tiempo, Memoria, Mentiroso, Pares, Premiado, Ruleta Rusa | **Sin límite** | No aplica | Sin límite |

**Decisión del user:** solo los medianos llevan cap. Pesados y ligeros son libres para free users, porque el contenido es denso pero re-jugable, y los ligeros son loops cortos. Los 5 medianos son los más susceptibles a "grinding" sin pagar.

**Reset:** medianoche local (vía `DateTime.now()` comparado contra `lastDailyResetDate`).

### 2.3 Mecánica del anuncio rewarded

- Trigger: usuario toca EMPEZAR en juego con `remainingPlays == 0` (y no premium).
- Modal/bottom sheet: "Ya jugaste X hoy. Ver anuncio para 1 más, o hacerte Premium."
- 2 botones:
  1. **Ver anuncio** (1 video rewarded de 15-30s) → +1 jugada para ese juego específico, hoy.
  2. **Obtener Premium** → navega a paywall.
- Ad provider: **Google AdMob** via `google_mobile_ads` package (test IDs en dev, producción en release).
- **Cooldown: ilimitado** (decisión user). Confiamos en AdMob para rate limiting per-session. Sin cap diario en la app.

### 2.4 Paywall (Premium)

Pantalla `lib/screens/paywall/paywall_screen.dart` con:
- Lista de beneficios (sin caps, sin anuncios, hot mode gratis).
- Botón **"Comprar Premium — $4.99"** (In-App Purchase, Google Play Billing).
- Botón **"Restaurar compras"** (cross-device).
- Disclaimer: "Pago único. No se renueva."
- Manejo de errores: payment canceled, network error, already owned, pending.

### 3.2 Provider nuevo: `MonetizationProvider`

Separa concerns de `SettingsProvider` (preferencias de usuario) vs monetización (reglas de negocio). Sigue el mismo patrón de `ChangeNotifier` + `LocalStorage`.

```dart
class MonetizationProvider extends ChangeNotifier {
  bool _isPremium = false;
  DateTime _lastDailyReset = _today();
  Map<String, int> _dailyPlayCounts = {};
  bool _isLoaded = false;
  bool _adsAvailable = false;        // false en web (no usamos, pero por si)
  bool _billingAvailable = false;    // false en web

  // ── Public API ──
  bool get isPremium;
  int remainingPlays(String gameName);
  bool canPlay(String gameName);          // true si puede arrancar el juego
  Future<void> recordPlay(String gameName);  // llamar DESPUÉS de EMPEZAR
  Future<bool> watchAdForGame(String gameName);  // returns true si granted (sin cooldown)
  Future<void> purchasePremium();
  Future<void> restorePurchases();
  bool get adsAvailable;                  // false en web
  bool get billingAvailable;              // false en web

  Future<void> load();                    // lee de LocalStorage
  Future<void> resetDailyIfNeeded();      // interno, llamado en load() y on resume
}
```

**Lógica de cap:**
```dart
int remainingPlays(String game) {
  if (isPremium) return 999;  // sentinel
  if (!isCapped(game)) return 999;       // tier ligero
  final cap = _capFor(game);
  final used = _dailyPlayCounts[game] ?? 0;
  return (cap - used).clamp(0, cap);
}
```

### 4.3 Patrón de inyección (idéntico en los 14 start screens)

```dart
// En _buildStartButton, antes del Navigator.push:
Future<void> _onStart() async {
  final monetization = context.read<MonetizationProvider>();
  final canPlay = monetization.canPlay('game_name_here');
  if (!canPlay) {
    final result = await PlayLimitModal.show(
      context: context,
      gameName: 'Preguntas',
    );
    if (result == PlayLimitResult.canceled) return;
    // result = watchedAd | purchasedPremium
    if (result == PlayLimitResult.canceled) return;
  }
  // ... existing code: create controller, navigate ...
  monetization.recordPlay('game_name_here');
}
```

Una **abstracción** más limpia: extraer un helper `GateGuard.guardStart(context, gameName, onAllowed)` que hace todo el flujo (canPlay check, modal, ad, premium navigation, recordPlay). Reduce la duplicación a **1 línea por start screen** en vez de 15.

```dart
// lib/widgets/gate_guard.dart
class GateGuard {
  static Future<bool> tryStart(
    BuildContext context, {
    required String gameName,
  }) async {
    final monetization = context.read<MonetizationProvider>();
    if (monetization.canPlay(gameName)) {
      await monetization.recordPlay(gameName);
      return true;
    }
    final result = await PlayLimitModal.show(context, gameName: gameName);
    switch (result) {
      case PlayLimitResult.watchedAd:
        return true; // ad granted, ya se llamó recordPlay internamente
      case PlayLimitResult.purchasedPremium:
        return true; // premium, ya sin caps
      case PlayLimitResult.canceled:
        return false;
    }
  }
}
```

Uso en cada start screen: `if (!await GateGuard.tryStart(context, gameName: 'preguntas')) return;`

## 9. Riesgos

| Riesgo | Mitigación |
|--------|-----------|
| **AdMob fill rate bajo en algunas regiones** | Fallback gracioso: si ad falla, ofrece premium con descuento temporal o +2 jugadas como bonus. |
| **IAP receipt validation falla** | Usar `in_app_purchase` server-side validation opcional. v1: confiar en local cache + restore en cada launch. |
| **User compra en Android, juega en iOS** | No hay iOS app. Si en futuro se publica iOS, validar con mismo service account. |
| **User borra cache de app → pierde `isPremium`** | `restorePurchases` en cada launch como safety net. Botón "Restaurar" siempre visible. |
| **Reset data borra premium por accidente** | `resetAllData` ahora **preserva** `isPremium` (cambio explícito en este plan). |
| **Web deploy muestra UI rota de premium** | Banner + premium auto-active evita esto. |
| **Cambiar caps en producción** | Caps son constants en código. Para v1 está bien. v2: remote config. |
| **User usa ad blocker en Android** | `google_mobile_ads` no se puede bloquear client-side. OK. |
| **Ad muestra contenido inapropiado** | AdMob tiene controles de brand safety; configurar en dashboard. |
| **Play Console review rechaza IAP setup** | Seguir guía oficial de `in_app_purchase` package, declared products antes de submit. |

## 11. Notas de implementación

### 11.1 IAP en Flutter — gotchas

- `in_app_purchase` 3.x usa `InAppPurchase.instance` singleton — fácil de mockear con `InAppPurchase` factory pattern.
- `ProductDetails` debe estar cargado ANTES de mostrar paywall. Call `IAPConnection.queryProductDetails([id])` en init.
- Receipt validation: para non-consumible simple, basta con guardar `isPremium=true` localmente y verificar via `restorePurchases()` en cada launch.
- Pendiente state: si user inicia purchase y cierra la app, en próximo launch el `PurchaseDetails` queda en `PurchaseStatus.purchased` → restaurar.
- Errors: `PurchaseStatus.error` con `error.code` (PlatformException). Mapear a mensajes user-friendly.

### 11.2 AdMob en Flutter — gotchas

- `google_mobile_ads` requiere init en `main()` antes de `runApp` via `MobileAds.instance.initialize()`.
- `RewardedAd.load()` async, cachear la próxima ad cuando se muestra la actual.
- `onUserEarnedReward` callback fires al completar el video. Si no completa, NO rewarded.
- Test IDs: `ca-app-pub-3940256099942544/5224354917` (rewarded). Reemplazar con real IDs en release.
- AndroidManifest: agregar `<meta-data android:name="com.google.android.gms.ads.APPLICATION_ID" android:value="@string/admob_app_id"/>`.
- iOS: Info.plist `GADApplicationIdentifier`. (No aplica en v1, sin iOS app).

### 11.3 Web handling (mínimo)

**Decisión user: no hay web.** No escribimos código de web handling. Las implicaciones:
- AdMob en web: el package tiene web support limitado; `RewardedAd` específicamente no funciona. Si la app se abre en web, `showAd()` debe fallar gracefully (return false) sin crashear.
- IAP en web: `in_app_purchase.isAvailable()` retorna false. `purchasePremium()` debe detectar esto y mostrar error.
- No se muestra ningún banner "Compras solo en Android". Los usuarios de web descubren por su cuenta que no pueden comprar.
- Build web sigue deployando (gh-pages workflow intacto) pero sin funcionalidad de monetización.

**Mínimo code defensivo** (sin lógica de "premium auto-active en web"):
```dart
// En AdService.showAd
if (kIsWeb || !_initialized) return false;

// En BillingService.purchase
if (!InAppPurchase.instance.isAvailable()) {
  throw 'Compras no disponibles en esta plataforma';
}
```
